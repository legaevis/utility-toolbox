# Typograf — Typography Engine Documentation

Полная документация раздела «Типограф» (id: `typography`). Реализует
«Эталонные правила типографирования» (§1–40) и спецификацию «Доработка
типографа: правила, контекст и безопасная обработка текста» (§1–30);
ссылки на параграфы даны как (§N). English where it matters for another
AI/developer.

Актуально для **v0.17.0**: 100 правил, 17 категорий, 160 символов,
333 теста.

---

## 1. What it is

«Типограф» приводит текст к типографским нормам: умные кавычки, тире,
неразрывные пробелы, спецсимволы, математика, числа, даты, время, валюта,
единицы измерения, телефоны, номера, сокращения — плюс панель быстрого
копирования символов. Вся обработка выполняется **локально и синхронно**;
ни один символ пользовательского текста не покидает приложение.

**Главный принцип (§38): менять ФОРМУ, не меняя СМЫСЛ.** Никаких слепых
глобальных замен — каждое правило проверяет контекст. Не исправляются:
фактические ошибки, стиль автора, имена собственные (кроме узкого белого
списка §20), неизвестные сокращения, технический код. Орфография — отдельный
инструмент приложения (Spell Checker). Если есть сомнение — правило
НЕ исправляет.

## 3. Engine flow (§37)

```
input
  → normalize line endings (\r\n → \n)
  → optional keyboard-layout fix (reuses switchLayout)
  → Unicode NFC normalization
  → protect(): ```code```, `inline`, кодовые строки (const/let/import/…),
               CSS-декларации, snake_case, HTML tags & entities, URLs, emails
               → U+E000-delimited tokens (§33)
  → language: options.language or detectLanguage()
  → RULES, sorted by priority — each guarded by:
      category toggle · language (appliesTo) · aggressive flag · try/catch
  → restore() tokens verbatim
  → output (+ fired-category stats)
```

### API

```ts
typograf(input, options?): string
typografDetailed(input, options?): { text, fired: Partial<Record<RuleCategory, number>> }

options: {
  language?: 'auto' | 'ru' | 'en';       // default 'auto'
  categories?: Partial<Record<RuleCategory, boolean>>;
  fixLayout?: boolean;                    // default false (rewrites letters)
  aggressive?: boolean;                   // default false (§36)
}
```

Default categories: всё ВКЛ, кроме `yo` (переписывает буквы — opt-in, §7).

## 4. Contracts

- **Идемпотентность (§34)**: `typograf(typograf(x)) === typograf(x)` — есть
  батарея тестов, включая агрессивный режим. Ловушки, пойманные тестами:
  пробел после запятой не должен срабатывать внутри `12,5`; группировка
  разрядов не должна резать телефоны (телефоны идут раньше чисел);
  «поедающие» префиксные группы в regex ломают цепочки соседних слов —
  использовать lookbehind; двухтокенные паттерны не прокатывают цепочку
  инициалов — клеить по одному шагу с lookahead.
- **Структура текста (§32)**: абзацы, нумерованные и маркированные списки,
  переносы строк сохраняются; удаляются только 3+ подряд пустые строки.
  Маркер списка `- ` НЕ превращается в тире, если соседние строки — тоже
  элементы списка (прямая речь остаётся прямой речью).
- **Защита (§33)**: URL, email, HTML-теги с атрибутами, HTML-сущности,
  fenced/inline код, кодовые строки (начинающиеся с `const`/`let`/`var`/
  `function`/`import`/`export`/`return`/`if`/`for`/`while`), CSS-декларации
  (`font-size: 14px;`), snake_case-идентификаторы, IPv4-адреса
  (`192.168.1.1`), hex-хэши (git SHA, md5 — 7–64 hex-символов, обязательно
  и цифра, и буква) и UUID заменяются
  PROTECTED-токенами (U+E000 — private use, в обычном тексте не
  встречается) и возвращаются без изменений.
- **NBSP настоящий U+00A0 (§30)**, группировка разрядов ru — U+202F (NNBSP),
  en — запятые.

## 5. Rule Engine (§40)

Каждое правило:

```ts
{
  id: 'space.afterPunct',        // уникальный, dot-namespaced
  name: 'Space after punctuation…',
  category: 'spaces',            // тумблер в настройках
  appliesTo: 'all' | 'ru' | 'en',
  priority: 130,                 // меньший — раньше; RULES отсортирован
  aggressive?: true,             // только в агрессивном режиме (§36)
  apply: (text) => text,         // чистая, идемпотентная функция
}
```

Диапазоны приоритетов (порядок конвейера — часть контракта):

| 100+ spaces | 200+ punctuation | 300+ quotes | 400+ specials | 450+ math |
|---|---|---|---|---|
| **500+ dates** | **550+ time** | **600+ dashes** | **650+ phones** | **700+ numbers** |
| **750+ currency** | **800+ units** | **850+ numero** | **900+ abbrev** | **950+ nbsp** |
| **1000+ hanging** | **1050+ yo** | | | |

Ключевые зависимости порядка: time и ISO-даты ДО тире (9-00 и 2026-08-25 не
должны стать диапазонами); диапазон с пробелами (608) ДО правил тире
предложения (610/615); телефоны ДО чисел (группировка не режет
89061234567); nbsp поздно (работает по финальным пробелам); hanging после
nbsp; yo последним.

## 7. English rules — сводка (v0.14–v0.15)

При «Язык текста: английский» (или автоопределении en) работают:
`quotes.en.double`, `quotes.en.single`, `dash.sentence.en`,
`date.capitalize.en`, `number.grouping.en`, `unit.space.en`,
`nbsp.initials.en`, `nbsp.honorifics.en`, `nbsp.ampm.en`,
`nbsp.ordinal.en`, `nbsp.numberUnit.en`, `hanging.serviceWords.en` —
плюс все правила `all`.

Эталон v0.15.0 (тест «english etalon sample»):

```
Вход:  "To be, or not to be — that is the question," said Hamlet 'the Dane' in Act 3, Scene 1.
       Prices range from $10.50 – $20.00 (a 50%-75% increase).
Выход: “To be, or not to be — that is the question,” said Hamlet ‘the Dane’ in Act 3, Scene 1.
       Prices range from $10.50–$20.00 (a 50%–75% increase).
```

Решения, зафиксированные эталоном: диапазоны цен/чисел/процентов — en dash
БЕЗ пробелов; прозаическое em dash с пробелами сохраняется (британский
стиль допустим); пунктуация внутри кавычек (`,”`) не переносится — позиция
запятой не меняется; переносы строк сохраняются.

## 8. Aggressive mode (§36, §27)

Тумблер «Агрессивное форматирование», по умолчанию ВЫКЛ. Включает правки,
меняющие редакционный стиль: `12.05.2026 г.` → `12 мая 2026 года`; диапазоны
дат и лет словами («с 25 по 31 августа 2026 года», «с 2020 по 2026 год»);
`тел.` → `телефону`; `руб.` → `₽` (точка в конце предложения сохраняется:
`вместо 2499 руб.` в конце → `вместо 2 499 ₽.`). Реализован флагом
`aggressive: true` — движок пропускает такие правила, пока опция выключена.
Даже в агрессивном режиме смысл текста не меняется (§27/§38).

## 9. Статистика и «Показать изменения» (§24, §25)

`typografDetailed()` возвращает `fired` — сколько правил каждой категории
РЕАЛЬНО изменили текст (правило включено, но ничего не поменяло — не
считается). UI показывает это в meta-строке. Рядом — кнопка «Показать
изменения (N)»: `diffChanges()` (processors/typograf/diff.ts, word-level
LCS) строит конкретные пары «было → стало» («"Привет" → «Привет»»,
`5-10 → 5–10`); до 50 пар, тексты больше ~1500 слов — фича тихо
отключается, чтобы не подвешивать UI.

## 10. Known deviations from the reference examples

- `6.5 дюймов` → `6,5 дюймов` (эталон показывает «дюйма»): согласование
  падежа — морфологическая правка, меняющая слово; запрещено §38.
- Пример 3 эталона заменяет `.` на `;` между вариантами — редакционная
  правка пунктуации, не выполняется (тесты §39 T9/T10 проверяют варианты
  по отдельности).
- `9-30` не конвертируется во время (только `-00`): иначе `5-10` перестало
  бы быть диапазоном. Ограничение задокументировано в правиле time.hyphen.

## 14. How to extend

1. Добавь правило в нужный массив в `rules.ts` с полным набором метаданных
   (id, name, category, appliesTo, priority, aggressive?). Приоритет —
   в диапазоне своей категории; порядок — часть контракта (§5 выше).
2. Правило обязано быть идемпотентным и контекстным (не слепой replace).
   Невидимые символы в коде и тестах — ТОЛЬКО `\uXXXX`-эскейпами.
3. Тесты: само преобразование + «что НЕ должно трогаться» + идемпотентность.
4. Новая категория: расширь `RuleCategory`, `DEFAULT_CATEGORIES`,
   `RULE_CATEGORIES`, локали `ruleCats` (en+ru), группу в `RULE_GROUPS`
   (Typograf.tsx) — TypeScript укажет пропуски.
5. Новые символы: `SYMBOLS` в symbols.ts, невидимые — только `\uXXXX` +
   `display`; уникальность проверяется тестом.
6. Обнови каталог в этом файле (раздел 6) — документация обязана
   перечислять все правила.
